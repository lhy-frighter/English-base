## 1. 需求复述（来自用户）

1. **中文兜底（code-switching）**：对话中忘记某句英文怎么说时，直接打/说中文（允许中英混说），AI 理解并给出地道英文表达与讲解，可加入复习集（地道口语、描述性表达等）。
2. **AI 说的内容可收藏**：AI 用到的词可一键加入词卡；句子/表达、语法点也应成为可复习对象——「英语学习需要的不只是词语」。
3. **深度联动**：与阅读、跟读、考试、今日页、仪表盘打通；资产可积累、可重逢、可点回来源、可下钻。

## 2. 调研结论（GitHub / 学术）

### 2.1 理论依据：词块法（Lexical Approach, Michael Lewis 1993）

- 流利语言的基本单位不是单词或抽象语法规则，而是**预制词块（chunks）**。原始研究数字（Erman & Warren, 2000, *Text* 20(1)）：程式语占**口语语篇 58.6%、书面语篇 52.3%**；Howarth (1998) 对书面语的估测约 40%。「50–80%」是二手教学文章的宽泛区间，本方案以原始数字为准。学词块降低认知负荷、加快处理速度、听起来更地道。
- 来源：[Erman & Warren 2000, DOI 10.1515/text.1.2000.20.1.29](https://doi.org/10.1515/text.1.2000.20.1.29)、[The Idiom Principle Revisited (2015)](https://academic.oup.com/applij/article/36/5/549/167093)
- Cambridge Papers in ELT 词块分类（资产分类对齐）：collocation 搭配 / bundle 词束 / formulaic sequence 程式语 / sentence frame 句型框架。
- 来源：[Cambridge Papers in ELT: Learning language in chunks (2019)](https://www.cambridge.org/ru/files/3815/6941/9472/CambridgePapersInELT_Chunks_2019_ONLINE.pdf)

### 2.2 句子挖矿（sentence mining）业界做法

- **asbplayer**：一张卡 = 原句 + 目标词 + 释义 + 音频 + 来源 URL（字段 Sentence/Word/Definition/Audio/Source），可一键挖矿。[asbplayer mining docs](https://docs.asbplayer.dev/docs/getting-started/mining-subtitles/)
- **VocabSieve**：句子挖矿伴侣，理念是「以最小摩擦把句子送进复习」。[VocabSieve](https://libraries.io/pypi/vocabsieve)
- 词卡打基础，句卡服务中级以上；语法与搭配通过语境 incidental 习得。[Sentence Cards](https://mikeydoes.com/glossary/sentence-cards/)

### 2.3 语法卡的有效形态

- 语法在 SRS 中**必须语境化**：挖空 / 句型转换 / 找错；抽象规则卡（「conjugate X」）效果差。[SRS for language learning](https://longtermemory.com/b/spaced-repetition-language-learning/)

### 2.4 最直接对标：pi-language-tutor（MIT，2026-08 仍更新）

- 仓库（github.com/mackt/pi-language-tutor，v0.5.0）已 clone 到 `research/` 逐文件核对：
  - **没有本地语言分类器**：`core.ts` shouldSkipCheck 只做闸门（命令/代码/过短/符号堆；CJK 按字计数），**模式 check/tutor/skip 由 LLM 在同一次调用的 JSON 里裁决**。
  - **两个面板永不并出**：学习语言 → Writing check；母语 → Writing tutor（自然整句 + 关键词 + 承载语法）。
  - `flashcards.ts`：ts-fsrs、`enable_short_term:false`；tmp+rename 原子写；mergeCards 防止复习窗口覆盖新卡；小写去重；introducedAt 控制新卡预算。
  - tutor 的词在它产品里自动存卡；**本方案改为用户显式确认**（质量闸）。
  - 教学/翻译面板**绝不回送 LLM**。
- **执行链差异（v1.2 明确）**：pi 是额外发起一个**非阻塞 review 调用**决定模式，失败不影响主对话；V9 是让**主对话流输出正文 + [TEACH] 尾块**。模式思想相同，工程链路不同，TEACH 尾块的安全约束见 §4.2。
- 旁证 **lingo-loop**（MIT，local-first，YAML 画像 + SQLite；星标 0，仅作模式佐证）：[PyPI](https://pypi.org/project/lingo-loop/)。

### 2.5 语码转换（code-switching）工程要点

- 采用「本地闸门 + LLM 同次裁决模式」，不写比例分类器；短中文（「怎么说？」「我累了」）也是有效学习请求，必须放行（见 §4.1）。[Code-switching handling](https://theneuralbase.com/conversational-ai/learn/intermediate/code-switching-handling/)

## 3. 架构升级：独立学习资产层（核心决策）

### 3.1 决策：新建 `learning_assets`，不污染 lexemes

现状：`lexemes(lemma,pos,sense) → notes → cards(FSRS)`。**lexemes 不只是存储表，它还是「已掌握词集合」的事实源**——阅读标注、严格覆盖率、考纲覆盖率、漏网词（unknown_encounters）、增长统计全部依赖它。

v1.1「给 lexemes 加 asset_kind、把 __concept__ 回填 grammar」被否决，原因：
- 把词块/语法伪装成单词，会进入覆盖率与已知词统计，污染能力指标；
- `__concept__` 是考试错因/策略/知识点的通用容器，**不等于语法**，批量标 grammar 是语义错误。

**v1.2 方案：独立资产表 + 统一调度 + 多来源证据。**

- `cards / review_log / FSRS` 继续共用（调度器统一）；
- **严格覆盖率、已知词集合、考纲覆盖率、漏网词只读取 lexemes（word）**，与新资产物理隔离；
- word 类资产关联现有 lexeme，单词的成卡仍走现有 note/card 管线，不重复调度。

### 3.2 表结构（migration v14，契约见 §8 附录）

```sql
-- learning_assets：identity_key 是语义身份（跨入口只建一次）；idempotency_key 是写操作 nonce
CREATE TABLE learning_assets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  asset_kind TEXT NOT NULL CHECK (asset_kind IN ('word','chunk','grammar','pronunciation','concept')),
  canonical TEXT NOT NULL,
  gloss TEXT NOT NULL DEFAULT '',
  payload_json TEXT NOT NULL DEFAULT '{}' CHECK (json_valid(payload_json)),
  lexeme_id INTEGER,
  identity_key TEXT NOT NULL,
  content_hash TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','archived','tombstoned')),
  created_at INTEGER NOT NULL,
  confirmed_at INTEGER NOT NULL DEFAULT 0,
  idempotency_key TEXT NOT NULL,
  CHECK ((asset_kind = 'word') = (lexeme_id IS NOT NULL)),  -- word 必有 lexeme，非 word 不得有
  UNIQUE(asset_kind, identity_key),
  UNIQUE(idempotency_key)
);
CREATE INDEX idx_assets_kind_created ON learning_assets(asset_kind, created_at);
CREATE UNIQUE INDEX idx_assets_word_lexeme ON learning_assets(lexeme_id)
  WHERE asset_kind='word' AND lexeme_id IS NOT NULL;  -- 一个 lexeme 至多一个 word asset

-- 多来源相遇：locator_hash 区分同篇不同位置；删来源只改 source_status
CREATE TABLE asset_encounters (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  asset_id INTEGER NOT NULL REFERENCES learning_assets(id) ON DELETE CASCADE,
  origin_kind TEXT NOT NULL CHECK (origin_kind IN ('reading','conversation','shadow','exam','syllabus')),
  origin_ref TEXT NOT NULL DEFAULT '',
  locator_json TEXT NOT NULL DEFAULT '{}' CHECK (json_valid(locator_json)),
  locator_hash TEXT NOT NULL DEFAULT '',
  title_snapshot TEXT NOT NULL DEFAULT '',
  sentence_snapshot TEXT NOT NULL DEFAULT '',
  content_hash TEXT NOT NULL DEFAULT '',
  source_status TEXT NOT NULL DEFAULT 'active' CHECK (source_status IN ('active','deleted')),
  encountered_at INTEGER NOT NULL,
  UNIQUE(asset_id, origin_kind, origin_ref, locator_hash)
);
CREATE INDEX idx_enc_origin ON asset_encounters(origin_kind, origin_ref);

CREATE TABLE asset_relations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  from_asset INTEGER NOT NULL REFERENCES learning_assets(id) ON DELETE CASCADE,
  to_asset INTEGER NOT NULL REFERENCES learning_assets(id) ON DELETE CASCADE,
  rel TEXT NOT NULL CHECK (rel IN ('contains','exemplifies','pronunciation_of','variant_of')),
  detail_json TEXT NOT NULL DEFAULT '{}' CHECK (json_valid(detail_json)),
  CHECK (from_asset <> to_asset),
  UNIQUE(from_asset, to_asset, rel)
);

-- asset_evidence：多途径能力证据（区别于 review_log 的调度事实）
CREATE TABLE asset_evidence (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  asset_id INTEGER NOT NULL REFERENCES learning_assets(id) ON DELETE CASCADE,
  dimension TEXT NOT NULL,
  result TEXT NOT NULL CHECK (result IN ('correct','partial','wrong','improved','recurred','used_spontaneously')),
  source_kind TEXT NOT NULL CHECK (source_kind IN ('reading','conversation','shadow','exam','syllabus','review')),
  source_ref TEXT NOT NULL DEFAULT '',
  payload_json TEXT NOT NULL DEFAULT '{}' CHECK (json_valid(payload_json)),
  occurred_at INTEGER NOT NULL,
  idempotency_key TEXT NOT NULL UNIQUE
);
CREATE INDEX idx_evidence_asset ON asset_evidence(asset_id, occurred_at);
```

cards 表在 v14 内**重建**（标准 SQLite 重建，id 全保留，review_log 不受影响），归属严格 **XOR**：

```sql
-- note_id 与 asset_id 必须恰好一个非空；asset_id 外键到 learning_assets
CHECK (
  (note_id IS NOT NULL AND asset_id IS NULL) OR
  (note_id IS NULL AND asset_id IS NOT NULL)
)
-- asset_id INTEGER REFERENCES learning_assets(id)；重建 idx_cards_due，新增 idx_cards_asset
```
### 3.3 类型专属载荷（payload_json）

| kind | canonical | payload 字段 |
|---|---|---|
| `chunk` | 词块原文 | `variants[]` 变体、`zh_intent` 中文意图、`register` 语域（spoken/formal/…）、`example_en/zh` 完整例句 |
| `grammar` | 结构模板（used to + inf） | `exercise_form`（cloze/transformation/error_spotting）、`prompt`、`answer`、`explanation`、`counterexample` 反例 |
| `pronunciation` | 目标片段（thought /θɔːt/） | `ipa`、`problem_type`（segmental/liaison/stress/weakform/rhythm）、`minimal_pair{e1,e2}`、`perception`、`production_ref` 跟读记录引用 |
| `concept` | 考点名 | `test_point`、`error_reason`、`strategy` 解题策略、`original_question_ref`（attempt_id,q_index） |
| `word` | 词原形 | 关联 lexeme；载荷仅存冗余的相遇/语域提示，调度在词卡侧 |

### 3.4 卡片工厂：按类型成卡（不机械统一两张）

| kind | 生成卡片 | 说明 |
|---|---|---|
| word | 现有五卡策略（recognition/recall/cloze/spelling/l_recog） | 完全不变，走 note/card |
| chunk | `chunk_recall`（中文意图→主动回忆英文）+ `chunk_cloze`（例句挖空） | 2 张，音频复习时实时合成 |
| grammar | `grammar_pattern`：**一个具体练习生成 1 张**，后续可派生 | 语境化题，不做抽象规则卡 |
| pronunciation | `pron_perception`（听辨）始终建；`pron_production`（录音→ASR/对齐→人工确认）**产出链完成才建** | 听辨卡完成**绝不记为发音已掌握**、不提升口语指标 |
| concept | `concept_recall`：错误识别或策略回忆 1 张 | `__concept__` 保持 concept，不批量改 grammar |

### 3.5 共享组件：DictPanel + AssetCaptureSheet

- **`<DictPanel>`**（从 `App.tsx` 抽取，约 150 行内联 UI）：义项/英英回退/发音/成卡；props：word/phrase、textId、offset、compact。阅读、考纲、对话三处共用，行为不变。
- **`<AssetCaptureSheet>`（统一「转为练习」入口，v1.2 新增）**：

```text
阅读划选 / 对话气泡 / 跟读问题 / 考试错题
              ↓ 触发「转为练习」
   系统建议类型：词 / 表达 / 语法 / 发音 / 概念（可多选、可改）
              ↓
   用户确认、编辑、预览将生成的练习与卡片
              ↓
   统一资产服务：去重 → 相遇/关系 → 卡片工厂（幂等）
```

  - 关键原则：**系统建议类型，用户最终裁决**。例 `I'm looking forward to it`：整句→chunk；`look forward to doing`→grammar；其中单词→word；连读问题→pronunciation。
  - 所有入口只调这一个 sheet + 一个资产服务，杜绝各页面分别做「加词卡/存句子/加语法」。

### 3.6 与现有统计的边界（硬隔离）

- 覆盖率 / 已知词 / 考纲覆盖率 / unknown_encounters → **只查 lexemes**，迁移前后数字必须逐字一致（见 §6）。
- 仪表盘新增「资产」口径，但与「能力证据」分区展示（见 §4.4）。

## 4. 对话功能深化

### 4.1 输入边界：本地闸门（修订）+ LLM 裁决 + 显式入口

- `src/conversation/tutor-gate.ts`（纯函数 + 单测）**只拦截**：/、! 开头、代码围栏、空内容、符号噪声（字母/字符比过低）。
- **不再拦短内容**：「怎么说？」「我累了」「这个呢」「太尴尬了」等短中文一律送 LLM 裁决（可结合当前选中/上下文消歧）。
- 系统提示词要求模型在同一次调用内裁决 `chat / teach / skip`；混说、半句中文由模型处理。
- 提供两个**显式入口**（纠正错误裁决的出口）：「教我怎么说」（强制 teach）、「我只是想聊天」（强制 chat）。

### 4.2 说法教学：[TEACH] 尾块及其安全约束

主对话流式输出：可见英文正文 + 严格尾块（正文照常 TTS、对话不中断）：

```
[TEACH: {"en":"自然英文整句","zh":"整句意思",
  "chunks":[{"en":"词块","zh":"简释"}],
  "words":[{"en":"关键词","zh":"简释"}],
  "grammar":[{"structure":"...","note":"..."}]}]
```

- 解析器 `src/conversation/teach-parse.ts`（纯函数 + 单测：合法/损坏/缺字段/重复/截断/多块）。
- 教学面板：词块 chips、关键词 chips（走 DictPanel）、语法点 → 一律经 AssetCaptureSheet 由用户确认后成资产。
- **TEACH 安全约束（执行链不同于 pi，必须逐条验证）**：
  1. 流式期间 TEACH JSON 即被剥离，**不进气泡、不进 TTS**；
  2. 写入历史/committed_text 的只有可见英文，**TEACH 不进上下文**；
  3. **用户自己输入的 `[TEACH: ...]` 不得触发解析**（解析器只认模型回复尾部、由状态机标记的尾块，echo 的用户文本不解析）；
  4. 尾块截断/重复/非法字段 → **零写库**，降级普通对话；
  5. `TEACH.en` 必须与可见英文回复对应，对不上则丢弃尾块。
- 本地 3B 与云端 GLM 均可用；本地档 TEACH 稳定性进冻结评测，失败降级纯文本。

### 4.3 AI 内容可点可藏（全部走统一入口）

- assistant 气泡内单词可点 → DictPanel（word 走现有词卡管线）。
- 整句/短语悬停「转为练习」→ AssetCaptureSheet（建议 chunk/grammar，用户裁决）。
- 去重：同 `idempotency_key` 不重复建资产；再次遇到 → 追加 encounter（相遇 +1），并按遗忘/相遇度影响后续权重。

### 4.4 跨模块联动与仪表盘

- **阅读**：划选词或短语 → AssetCaptureSheet（word 走词卡，短语走 chunk/grammar）。
- **跟读**：问题词 → word（已有）；句子级读错 → chunk/grammar；发音问题 → pronunciation；shadow_sentence 毕业 → 一键转 chunk。
- **考试**：错题概念保持 **concept**（不伪装 grammar）；策略/错因进 concept 资产。
- **今日页/取卡**：FSRS 排程算法与每日配额继续共用；但**取卡查询、兄弟卡互埋、渲染 DTO 必须资产化**（现有 getDue 固定 JOIN notes/lexemes，asset 卡 note_id 为 NULL 会被误跳过或互埋）；互埋键统一为 `note:<id>` / `asset:<id>`。字段与所有权在 #139A 定死，渲染留 #142。
- **仪表盘三区分离**：①「创建资产」（按 kind 拆分）；②「完成复习」；③「真实能力证据」（锚定覆盖率等）。**成卡数量≠能力提升；pron_perception 成绩不提升口语指标**；主活动分钟口径不变（不重复计时）。
- 所有资产可点回来源；来源删除后显示「内容已删除」墓碑（tombstoned），不整条消失。

## 6. 封板硬验收闸门

1. 迁移前后已知词、严格覆盖率、考纲覆盖率、漏网词结果**完全一致**。
2. `__concept__` 保持 concept，不批量伪装成 grammar。
3. 同一表达从阅读、对话、跟读进入 → **只建一个资产、记录多次相遇**。
4. 所有资产可点回来源；来源删除后显示墓碑。
5. TEACH 控制块绝不进入气泡、历史和语音；用户输入的 TEACH 不解析。
6. 短中文与中英混说有冻结评测集，不只测 JSON 解析。
7. 看板区分「创建资产 / 完成复习 / 真实能力证据」，不把成卡数量当能力提升。
8. pronunciation 听辨成绩不提升口语能力指标。
9. 原 cards 全字段、ID、FSRS 状态及 review_log 关联逐行一致。
10. `foreign_key_check` / `integrity_check` / 孤儿卡检查全部为零。
11. 迁移重复执行不产生新表、新卡或任何数据变化。
12. 自动迁移前备份；后置校验失败必须整体回滚，不得启动半迁移数据库。

**业务测试（夹具）**：①同一资产经不同请求只建一次，但同一文章两个不同位置记两次 encounter；②队列中同时存在 ≥2 张 asset 卡时均可取出，不因 note_id=NULL 被互埋。

## 7. 风险与边界

1. **LLM 词块/简释质量**：LLM 是唯一来源，可能误释 → 一律用户确认后入库，不静默写入。
2. **本地 3B 的 TEACH 稳定性**：结构化输出可能退化 → 解析失败降级普通文本，坏数据零写库。
3. **外放声学误触发**：教学音频可能被 VAD 当成语音 → 维持戴耳机提示与现有 barge-in 灵敏度。
4. **不做内容硬锁**：资产按 FSRS 自然推进，不做阶段门硬解锁（既有原则）。
5. **许可证**：本方案不引入新依赖；词块为 LLM 生成 + 用户确认，无再分发版权问题。
6. **cards 重建风险**：v14 重建 cards 必须先在夹具库演练并校验行数/调度字段/review_log 关联，再应用于用户库。

## 8. 迁移附录 v1.2.1（#139A 契约）

### 8.1 identity_key 生成规则（按类型）

| kind | identity_key | 说明 |
|---|---|---|
| word | `lex:<lexeme_id>` | 一个 lexeme 至多一个 word asset（部分唯一索引） |
| chunk | `chk:<规范化英文表达>` | lowercase、空白折叠、弯引号归一 |
| grammar | `gra:<规范模板>|<exercise_form>` | 模板 + 练习形式联合身份 |
| pronunciation | `pron:<目标片段>|<problem_type>` | 片段 + 问题类型 |
| concept | `con:<paper_id>:<q_index>:<考点hash>` | 稳定业务键，不随文案变化 |

- idempotency_key 只代表一次写操作（IPC 重试/双击防重），**不承担语义身份**；语义查重先按 identity_key，命中则转走「追加 encounter」分支。

### 8.2 asset_evidence：多途径能力证据

- 定位：`review_log` 是**调度事实**（卡片评分→FSRS）；`asset_evidence` 是**能力证据**（任意学习途径都可写入），二者不互相替代。
- 典型记录：
  - 阅读中正确理解某 chunk（chunk_understood, source=reading）；
  - 对话中主动使用某表达（result=used_spontaneously, source=conversation）；
  - 语法改写/找错成功（grammar_transform_ok / grammar_error_spot）；
  - 跟读中发音问题 recurred 或 improved（source=shadow，payload 带相似度/时间戳）；
  - 考试中某 concept 答对（source=exam）；
  - FSRS 卡片复习结果（source=review，payload 带 card_id/rating）。
- 每条证据带独立 idempotency_key，同一事件不重复计；仪表盘「真实能力证据」区只读本表与 coverage_assessments。

### 8.3 来源删除的墓碑语义

- 删除一篇文章/一次会话来源：**只把对应 encounter.source_status 置为 deleted（保留标题/句子快照）**，资产与卡片保留；
- 资产仍有其他 active encounter 时状态不变；没有任何 active encounter 也不自动 tombstone（卡片复习可能仍在进行），仅在看板/列表降权；
- 禁止因删除单一来源而把整个资产标 tombstoned。

### 8.4 迁移操作流程

1. 迁移前自动复制 user.sqlite 到带时间戳的备份；记录迁移前覆盖率/已知词/漏网词快照与 cards、review_log 行数；
2. 每版迁移在同一事务内完成（DDL + PRAGMA user_version），函数体可重入（IF NOT EXISTS/列检测）；
3. 迁移后执行：覆盖率快照比对、cards 逐行比对、foreign_key_check、integrity_check、孤儿卡查询；
4. 任一项失败 → 恢复备份、保留原 user_version、中止启动，不允许半迁移库上线。
