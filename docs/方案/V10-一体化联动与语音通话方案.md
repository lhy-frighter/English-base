# V10 一体化联动与语音通话方案

> 版本：v1.0（2026-09-25）
> 前置：V9 资产底座（learning_assets / asset_encounters / asset_relations / asset_evidence + cards XOR，migration v14）已封板。
> 目标：把现有"单向、手动、终点式"的模块关系，升级为"环形、自动、互相回写"的一体化学习系统；最后以**全双工语音通话**收口"最后一公里"。
> 商业化：继续暂缓，本方案只服务自用与产品成熟度。

---

## 1. 核心设计：一个画像，四个机制

### 1.1 一个画像

所有模块只读写同一个学习者画像（V9 资产层 + 既有事实表）：

- 资产：word / chunk / grammar / pronunciation / concept
- 证据：asset_evidence（correct / partial / wrong / improved / recurred / used_spontaneously）
- 调度：cards + FSRS（review_log）
- 相遇：asset_encounters（reading / conversation / shadow / exam / syllabus）
- 派生优先级：`priority = 遗忘/复发次数 × 等级与考试权重 × 近期错误 × 输出型弱点加权`（查询时现算，不物化）

任何模块不得再自建一套"掌握状态"。

### 1.2 四个机制

1. **相遇即证据**：任何模块遇到已学资产自动追加相遇；阅读重现、对话听到、跟读练到、考试考到；用户**主动用出** = `used_spontaneously`（最高权重）；出错 = `recurred` 并自动提权。用户不再需要专门点"转为练习"，表单只在需要编辑细节时打开。
2. **弱点即调度信号**：priority 同时喂给三处——每日好文选材、对话引导（system prompt 注入）、今日页唯一下一步。
3. **双向深链 + 墓碑**：资产能点回所有来源；来源页能看"这里产出/掌握了什么"；来源删除只墓碑化相遇并保留快照。
4. **会话自动复盘（Debrief）**：读完一篇、聊完一场、跟完一组、考完一套、通话一通，自动出"本次收获"——新增资产、已改善、仍薄弱、建议下一步，批量确认、零表单。

## 2. 数据契约改动（migration v15）

### 2.1 shadow_sentences 加来源（跟读达标回写用）

```sql
ALTER TABLE shadow_sentences ADD COLUMN origin_kind TEXT NOT NULL DEFAULT 'reading';
  -- reading / conversation / voicecall
ALTER TABLE shadow_sentences ADD COLUMN origin_ref TEXT;
```

> 现有跟读句默认 reading。对话/通话送入的句子记 conversation / voicecall + 对应会话 key，达标后据此回写来源。

### 2.2 asset_evidence 扩展来源

`source_kind` CHECK 增加 `'voicecall'`（表重建，标准 foreign_keys OFF/ON 流程）。

### 2.3 语音通话记录表

```sql
CREATE TABLE voice_calls (
  call_key TEXT PRIMARY KEY,
  topic TEXT,
  target_pack TEXT,              -- cet6_speaking / ielts / free / review_today
  started_at INTEGER NOT NULL,
  ended_at INTEGER,
  duration_ms INTEGER NOT NULL DEFAULT 0,
  provider TEXT NOT NULL DEFAULT 'glm-realtime',
  model_revision TEXT,
  transcript_json TEXT NOT NULL DEFAULT '[]' CHECK(json_valid(transcript_json)),
  debrief_json TEXT NOT NULL DEFAULT '{}' CHECK(json_valid(debrief_json)),
  status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active','deleted'))
);
```

- 通话沉淀不另起事实源：教学点 → captureAsset；用出表达 → asset_evidence(source_kind='voicecall')；通话分钟 → learning_sessions(kind='voicecall')。
- 通话转写快照存 transcript_json，作为深链内容快照；删除通话只置 deleted，不连带删除资产。

### 2.4 迁移与验收要求（沿用 v14 规则）

- 迁移前自动备份（pre-v15-ts.sqlite，留 5 份）；每版迁移与 user_version 推进同事务；可重入。
- 后置校验：integrity_check、foreign_key_check、cards/review_log/资产各表计数无漂移；失败整体回滚。

## 3. 任务切片

### S13-a：会话自动复盘 + 反向视图 + 跟读 inline drill

**A. 跟读台发音 UX 改版（收口上一轮调研结论）**

- 问题词点击改为**就地小卡片（inline popover）**，不再串弹层：
  - 模型音 / 我的录音两个播放键（复用现有切片播放）；
  - 系统**建议问题 tag**：疑似替换→音素、漏词→弱读、卡顿 pill→节奏；一键可改（连读/重音/弱读/节奏/音素）；
  - 主按钮「🎙 再读这个词」：录单词 → 即时复判，达标显示 ✓（ELSA 式 repeat-to-green）；
  - 次按钮「存入复习」：用当前 tag 一键建发音资产（听辨+产出卡），零表单；
  - 「详细编辑」才打开 AssetCaptureSheet（高级入口）。
- 句级三分（现有对齐数据现算）：**准确度 / 完整度 / 流利度**；韵律在 S14 云端通话/评估前只做弱标注，不宣称音素评分。
- 单词重练达标自动写 asset_evidence（recurred→improved）；无资产则静默建发音资产，不打断流程。

**B. 自动复盘（Debrief）**

- 读完一篇文章（离开/点"完成"）、对话结束、考完一套：弹出复盘条——
  - 本次新增词/表达/语法/发音点（列表，默认全选，可取消）；
  - 已改善项、仍薄弱项；
  - 建议下一步（送跟读 / 开始复习 / 再来一篇同级）；
  - 一键确认，选中项批量走 captureAsset，已存在的只追加相遇。

**C. 来源反向视图（已学地图）**

- 文章顶部：已学 X 词、Y 表达、Z 句已跟读达标；可点进对应资产。
- 对话结束页：本场会话沉淀清单（资产 + 用出证据）。

**DoD**：0 号用户走"读一篇→复盘→问题词就地重练到绿"全程不打开大表单；复盘重复点击不重复建卡（幂等）；47 链 + 新增链全绿、tsc=0、build=0。

### S13-b：主动用出证据 + 复习卡"再用一次"

- **用出检测**：用户每轮对话发送时，将其英文文本与已学 word/chunk 资产做匹配（规范化 + 短语包含），命中即写 `used_spontaneously` 证据（每资产每会话一次，幂等）。中文轮、TEACH 教学轮不计。
- 证据回写资产卡面：复习时背面显示"你在 X 场对话/通话中主动用过 N 次"。
- **复习卡「再用一次」**：word/chunk/grammar 卡背面加按钮 → 跳对话页并带入引导指令（AI 引导用户把该资产用出来，至少一来回），用出后回写证据、卡片标记"已输出练习"。

**DoD**：构造含已学资产的用户轮，证据落库且重放不重复；"再用一次"链路闭环；测试链覆盖。

### S13-c：弱点跨模块调度

- **好文选材**：每日推荐在"严格覆盖率 + CEFR"基础上，提升 priority 高的资产在候选文章中的复现权重（优先选包含近期弱点词/结构的文章），推荐理由明示。
- **对话引导**：会话开始时把近期 pronunciation/grammar 弱点注入 system prompt（AI 刻意使用该结构、引导用户说，但不打断正常对话节奏）。
- **今日页调度器**：唯一下一步综合 ①到期复习（含逾期）②断点续学位置 ③近期高 priority 弱点 ④能力测评差距，给出一个主按钮 + 次级入口；规则可解释、可在设置页查看。

**DoD**：构造弱点资产后，推荐/对话/今日三处均出现对应信号；信号只影响优先级不硬锁内容；看板不把"成卡数"当能力提升。

### S13-d：跟读达标回写 + 考试错题跨域

- **跟读达标回写**（migration v15）：从阅读/对话/通话送入跟读的句子，达标（相似度阈值 + 1/3/7 通过）后：
  - shadow_sentences 状态置通过，origin 回写；
  - 来源页对应句标「✓ 已跟读达标」（文章渲染时按 sentence_hash 匹配）。
- **考试错题跨域**：
  - 听力错题卡加「🎙 送跟读台精听」（题干/听力原句 → ShadowPage）；
  - 语法/词汇错题加「💬 开对话演练」（带考点进入对话，AI 就该结构对练）；
  - 考完复盘自动汇总"薄弱能力清单"并排进今日页。

**DoD**：三类来源的跟读句达标后均能回写标记；错题两个跨域入口闭环；v15 迁移真实库冒烟通过（备份/计数/回滚/可重入）。

### S14：语音通话（最后一公里）

**定位**：从"按键/免提半双工回路"升级为**自然全双工通话**——像跟真人打电话，是"读外网/论文→口语雅思→英语思维"主线的最终形态入口。

**S14-1 GLM-Realtime 限时 spike（不锁生产）**

- 通道：`wss://open.bigmodel.cn/api/paas/v4/realtime`（WSS）；
- 鉴权：浏览器 WebSocket 无法加 Authorization 头，按官方 Realtime 指南核实方案（URL query 一次性 JWT/key，spike 必须跑通并记录）；
- 采用 **Server VAD**（`turn_detection.type=server_vad`，服务端托管说话起止与打断 `interrupt_response`），客户端只负责持续推音频；
- 音频：AudioWorklet 采集 → PCM16 16kHz 单声道上行（`input_audio_buffer.append`）；下行 `response.audio.delta` 为 24kHz PCM16 base64 → 解码入队、无缝播放；
- 模型档位：`glm-realtime-flash`（9B，延迟优先）首测，`glm-realtime-air`（32B）对比质量；音色 7 选 1（默认 tongtong）；
- 真机记录：连接建立耗时、松说到首音 p50/p95、打断→静音/可录耗时、30 分钟连续通话稳定性与内存、弱网/断网恢复、外放回声（验证耳机要求）。

**S14-2 通话产品化与深度联动**

- **通话入口**：对话页顶部「📞 语音通话」；通话前选目标包：自由通话 / 六级口语 / 雅思口语 / **用今天复习的表达通话**（review_today，把今日到期资产设为必用词）。
- **通话中教学（语音版 tutor）**：
  - 不会说的地方直接说中文，模型理解并给出自然英文说法（语音 TEACH 同语义：先说英文，再简短解释）；
  - 语音指令"存下来/这个怎么拼"→ 服务端 function call 或客户端按转写标记教学点；
  - 通话以自然对话为主体，教学不喧宾夺主。
- **通话沉淀（自动）**：
  - 用户话术中命中已学资产 → `used_spontaneously`（source_kind='voicecall'）；
  - 教学点、卡顿/被纠正表达 → 通话结束复盘列表，批量确认走 captureAsset（chunk/grammar/pronunciation）；
  - 发音可疑句可一键「送跟读台检测」（复用 #149 链路）；
  - voice_calls 落库（transcript + debrief 快照）；通话分钟进仪表盘主活动。
- **通话复盘**：结束即出——本场用出 N 个表达、新学 M 个教学点、四维印象（流利/完整/准确/节奏，云端结果 + 本地统计）、建议下一步。
- **离线/失败兜底**：未配置云端或断网 → 退回现有 VAD + Whisper + Kokoro 免提回路（明确标注本地档、延迟与停顿差异）；云端发送必须有显式开关（cloud-consent 增加 realtime 音频独立项），key 走 safeStorage。
- **费用预期**：GLM-Realtime 音频 0.18 元/分钟；通话页显示本次时长与计费口径，不做自动长时通话。

**DoD（S14 封板）**：
1. 0 号用户完成 3 通真实通话（自由 / 目标包 / review_today 各一），全程自然打断无卡死；
2. 中文兜底教学、教学点批量成卡、用出证据、送跟读、通话复盘五条链路全部闭环且幂等；
3. 30 分钟连续通话无内存增长，断网/弱网有提示且能切本地档；
4. v15 迁移、voice_calls 深链与删除墓碑验证通过；
5. 全量测试（链 + tsc + build）全绿，交接文档更新。

## 5. 封板闸门（V10 整体）

1. 五个模块（阅读/对话/跟读/考试/通话）的学习信号全部汇入同一画像，无模块私有掌握状态；
2. 任意学习会话结束都有自动复盘，且所有批量写入幂等（重复确认零新增）；
3. "主动用出"证据在对话与通话中均可产生，并在复习卡面与能力区可见；
4. 弱点可跨模块复现与引导，但任何内容不硬锁；
5. 资产/通话均可点回来源，来源删除保留墓碑快照；
6. 仪表盘明确区分"投入（分钟/次数）"与"能力（证据/测评趋势）"，成卡数不作为能力指标；
7. 语音通话云端发送有独立显式同意与费用提示，本地兜底链路可用；
8. 迁移（v15）自动备份、可重入、失败整体回滚；全量测试全绿。

## 6. 风险与合规

| 风险 | 说明与对策 |
|---|---|
| 通话延迟不达标 | 端到端体验依赖网络与服务端；spike 用真机 p50/p95 数据裁决，flash/air 二选一；不达标则通话保持"免提回路"形态，不硬上 |
| 浏览器 WS 鉴权 | 无法加自定义头；按官方指南实现一次性凭证，禁止把长期 key 拼进可日志化 URL（如官方仅支持该方式，则只传短期 JWT） |
| 回声误触发打断 | 官方明确建议耳机；无耳机时客户端 VAD 降灵敏度并提示 |
| 云端音频隐私 | 复用 cloud-consent 体系并新增 realtime 独立开关；通话内容默认不做训练以外的二次使用，以平台条款为准并在设置内展示 |
| GPL 链路 | 通话为云端 API，本地 Kokoro 仍受 G2P GPL 约束（商业版 BLOCKED）；通话产品化不改变该结论 |
| 范围膨胀 | 严格按 #150→#158 顺序；每片超时先砍：考试跨域演练 → 来源反向视图 → review_today 目标包；核心（复盘/用出证据/通话主链）不砍 |
